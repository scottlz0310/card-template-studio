# v0.1.0 リリース前の実機 E2E ランブック

v0.1.0 を出す前に、実機（現場編集長 CALSMASTER のアルバム作成ツール `GhAlbum.exe`）と、このアプリの間で、
テンプレートを「作る → 書き出す → 本体に取り込む → 本体で使う → 本体から出し直す → このアプリで開き直す」まで
通しで確かめる手順。自動テストでは確かめられない「本体が受け付けて、思った見た目になる」ことを確かめるのが目的。

- 結果は「4. 実施記録」に書く（実施のたびに、日付・版・判定を足す）。
- 1 つでも「不合格」があれば、リリースしない。原因を直すか、既知の制約として「5.」に書いてユーザーの判断を仰ぐ。

## 0. 前提と安全

- 実施する PC: CALSMASTER Ver.25 が入っている開発 PC。**業務データ（実際の工事・写真）が無いこと**。
- 本体のテンプレート置き場（`C:\現場編集長data\DB14ACCESS\Template\`）に、E2E 用のテンプレートを足す。
  名前は `E2E_` で始め、終わったら **4. の後始末で消す**（本体が元から持つテンプレートには触らない）。
- 本体のアルバムは、使い捨ての「新規アルバム」だけを使い、**保存しない**（閉じるときは「保存しない」）。
- 書き出し先は、空の一時フォルダ（例: `C:\Users\dev\AppData\Local\Temp\cts-e2e`）。リポジトリや Dropbox の中に作らない。
- 検査するのは、リリース候補の `main` から作った **release ビルド**（`cargo build --release --locked`）。

## 2. 実機 E2E（B）

### 事前

1. A5 の `card-template-studio.exe` を起動できる状態にする。空の一時フォルダ `cts-e2e` を作る。
2. 本体 `GhAlbum.exe`（アルバム作成ツール）を起動し、使い捨ての新規アルバムを開く（分割数は後で変える）。

### B1: 起動

1. `card-template-studio.exe` を引数なしで起動する。

合格: ウィンドウが出て、タイトルが「新規テンプレート - カードテンプレート工房」。中央にカード（写真枠と 5 行）が描かれ、エラーの表示がない。

### B2: 新規作成 → 本体用に書き出す

1. 「ファイル」→「新規テンプレート…」（Ctrl+N）で、下の 3 つを順に作る（「写真枠と…の行を置いて始める」を選ぶ）。

   | テンプレート名 | 分割数  | 向き   | 期待する初期配置                 |
   | -------------- | ------- | ------ | -------------------------------- |
   | `E2E_1x3`      | 横1×縦3 | 縦向き | 写真が左・表が右                 |
   | `E2E_4x5`      | 横4×縦5 | 縦向き | 写真が上・表が下（文字が小さい） |
   | `E2E_1x1H`     | 横1×縦1 | 横向き | 写真が上・表が下                 |

2. それぞれ「ファイル」→「このテンプレートを本体用に書き出す…」で、書き出し先に `cts-e2e` を選ぶ（2 つ目以降は、同じフォルダに足す）。

合格:

- 3 つとも、カードの上に期待どおりの配置が出る（はみ出し・欠けなし）。
- `cts-e2e\TMPEXP\expinf` と、`TEMP1x3_V\E2E_1x3.TPL`・`TEMP4x5_V\E2E_4x5.TPL`・`TEMP1x1_H\E2E_1x1H.TPL` ができる。

### B3: 本体で取り込む

1. 本体のアルバム作成ツールで「カード」→「テンプレートのインポート」。
2. 「フォルダーの参照」の「フォルダー(F):」欄に `cts-e2e\TMPEXP` のパスを入れて OK。
   同名のテンプレートが本体にあるときは「上書きの確認」が出る。E2E 用だけなので「すべて上書き」でよい。

合格:

- 「テンプレートのインポートは正常に終了しました」（エラー・警告なし）。
- 本体のテンプレート置き場（`C:\現場編集長data\DB14ACCESS\Template\TEMP…\`）に、`E2E_…TPL` が、書き出した TPL とバイト単位で同一のまま入る（`cmp`）。

### B4: 本体で使う（見た目）

分割数ごとに、本体で次を行う。

1. 「分割数」（ツールバーの▼）で、B2 の表の分割数・向きに合わせる（横1×縦3 / 横4×縦5 / 横1×縦1 + 「用紙方向」→「横」）。
   ページをクリアする確認は「はい」。**本体の一覧は、いまのカードの分割数・向きに合うテンプレートだけを出す**ので、向きも合わせる。
2. 「テンプレートの適用/編集」で、「最新の情報に更新」を押し、`E2E_…` を選ぶ。プレビューを見てから OK で適用する。
   「ページやカードの新規作成時にこのレイアウトを用いる」は、**チェックを外したまま**にする（本体の既定を変えない）。
3. カードを画面で見る（1×1 横は、表がカードの下にあるのでスクロールする）。

合格:

- 適用できる（エラーなし）。
- 写真枠と 5 行（工種・種別・写真タイトル・撮影箇所・撮影年月日の、項目名と項目値）が出る。
- 配置が、このアプリの見た目と同じ向き（左右／上下）になり、カードの枠からはみ出さない。
- **項目名の文字が欠けない**。特に、`E2E_4x5` の「写真タイトル」が 1 行で、最後の「ル」まで読める
  （本体は、文字の左右に 3〜4.9pt の余白を取り、列に収まらない文字は折り返して、行からはみ出した分を隠す）。

### B5: 本体から出し直して、このアプリで開き直す

1. 本体で「カード」→「テンプレートのエクスポート」を行い、出力先に新しい一時フォルダ（`cts-e2e-out`）を選ぶ
   （本体のテンプレートが、すべて `TMPEXP` に出る）。
2. このアプリで「ファイル」→「エクスポートしたフォルダ（TMPEXP）を開く」から `cts-e2e-out\TMPEXP` を選ぶ。
   一覧（左の欄）は、分割数・向きの組ごとに並ぶ。スクロールして `E2E_1x3` を開く。
3. `E2E_1x3` で、カード上の「工種」ラベルを選び、**太字（B）にする**。ほかに、ラベルの文字を書き換え、
   「この行の下に行を追加」で 1 行足す（足した行は、すぐ下の行に重なる。この版の仕様）。
4. 「このテンプレートを本体用に書き出す…」で `cts-e2e` に上書きし（上書きの確認は「はい」）、本体で取り込み直し（「すべて上書き」）、
   `E2E_1x3` を適用する。

合格:

- 手順 1 で、本体の書き出しに `E2E_…` の 3 つが入り、元の TPL とバイト単位で同一。
- 手順 2 で、一覧に `E2E_…` と本体のテンプレートが出て、本体が書き出した TPL を、このアプリが開いて編集できる。
- 手順 4 で、本体のカードで、「工種」ラベルが太字になる。

注意: 本体は、項目に結び付いた（「対応する項目」がある）ラベルでは、「表示する文字」ではなく項目名を描く。
文字を書き換えても本体の画面には出ないので、反映の確認には、本体が必ず反映する書式（太字など）を使う。

### B6: 後始末

1. 本体のアルバムは、保存せずに閉じる。
2. 本体のテンプレート置き場から、E2E 用を消す: `C:\現場編集長data\DB14ACCESS\Template\TEMP*\E2E_*.TPL`。
3. 本体のテンプレート置き場に、取り込みで新しくできた空フォルダ（`TEMP4x5_V`・`TEMP1x1_H` など）があれば、空であることを確かめて消す。
4. 一時フォルダ `cts-e2e` と `cts-e2e-out`（照合用の `cts-e2e-chk` も）を消し、本体とこのアプリを終了する。

合格: `Template\` の下に `E2E` で始まるファイルとフォルダが残っていない。

## 3. 判定とリリース

1. A1〜A6・B1〜B6 がすべて「合格」なら、ユーザーに結果を報告する。
2. ユーザーの許可を得て、Prepare Release を実行する:
   `gh workflow run prepare-release.yml -f target_version=0.1.0`
3. 作られた PR（`chore(release): v0.1.0`）で、`Cargo.toml`・`Cargo.lock` の版が 0.1.0 になり、`CHANGELOG.md` の
   `[Unreleased]` が 0.1.0 の見出しに確定していることを確かめる。PR のレビュー（`APPROVED`）を待つ。
4. **この PR をマージすると、release.yml が動いて GitHub Release が公開される。公開は取り消しにくいので、マージはユーザーの明示的な許可を得てから行う。**
5. 公開後、Release の成果物（`card-template-studio-x86_64-pc-windows-msvc.zip` と `.sha256`）を取得して、チェックサムを照合し、
   展開した exe が起動することを確かめる。

#### 見つかったこと

- **F1（不合格 → 修正済み）**: 4×5 縦で、項目名「写真タイトル」が本体で折り返され、最後の 1 文字が欠けた。

  （1×3 縦は 76.9pt の列に 72pt の文字が収まり、4×5 縦は 63pt の列で 60pt の文字が折り返された）。
  修正: 余白を 7pt に見込み、横長の分岐は 12pt の項目名が収まる幅まで広げる。測定のテストも、本体の余白（4.9pt）で測る

- 所見（不具合ではない）:
  - 本体の `expinf` は、`Ver7.10Template` の次の行に、製品名と版（`現場編集長 CALSMASTER(25.0.0.0)`）の行がある。
    このアプリは `Ver7.10Template` だけを書くが、本体は問題なく取り込めた。
  - 本体は、「対応する項目」のある項目名ラベルでは、「表示する文字」ではなく項目名を描く（文字を書き換えても画面に出ない）。
  - 本体の「テンプレートの適用/編集」の一覧は、いまのカードの分割数・向きに合うものだけを出す。
  - 本体の適用画面の「ページやカードの新規作成時にこのレイアウトを用いる」が、開いたときにチェック済みだったことがある
    （手を触れていない）。外してから適用した。
  - このアプリの画面で、4×5 のような狭いカードでは、値の列の薄い見本文字（〈写真タイトル〉など）が切れて見える
    （実データではなく、見本表示）。

判定: B4 の不合格（F1）は修正し、修正後のビルドで本体の画面を再確認して合格。ほかはすべて合格。

## 5. 既知の制約（v0.1.0）

- 用途の確定していないバイト（#18）は、名前を付けずにそのまま保持し、画面から変更しない。
- カードの大きさは A4 ÷ 分割数（実機で 1×4 縦を測って確認）。物の配置の目安（緑の点線）は、既存テンプレートの実測から。
- 文字の見た目（影・袋文字の大きさなど）は、実機の画面を測った近似。
- 新規作成の初期配置の文字は、カードに収まるよう縮める（極端に小さいカードでは最小 1pt）。本体で見える大きさは、4×5 縦で 10pt、5×5 縦で 8pt など。
- 「この行の下に行を追加」は、足した行が、すぐ下の行に重なる（下の行を押し下げない）。
- 実機の確認は、本体の画面の見た目まで。印刷の確認と、実データ（写真）を入れた確認は、v0.1.0 の範囲外。
