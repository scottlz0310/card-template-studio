# カードテンプレート（.TPL）の仕様メモ

対象: 現場編集長 CALSMASTER Ver.25 のアルバム作成ツール `GhAlbum.exe`（MFC / x86、.NET ではない）。
`GhManageConstruction.exe` は .NET の管理画面で、テンプレートの読み書きは `GhAlbum.exe` 側にある。
アドレスは `GhAlbum.exe` の仮想アドレス。値はすべてリトルエンディアン、座標はインチ（double）。
文字列は cp932。「推定」と書いたもの以外は逆コンパイルした処理から読んだ値。

## 受け渡しの境界（カードメニュー → テンプレートのエクスポート／インポート）

```
TMPEXP\
  expinf                      "Ver7.10Template\r\n"（文字列 "Ver7" + ".10Template", 0x598d94 付近）
  TEMP{横}x{縦}_{H|V}\        H = 横向き, V = 縦向き（"%dx%d_%s", 0x585dec 付近）
    {テンプレート名}.TPL
```

## オブジェクトの見出し（44 バイト）

`OBJn`（n = 版の印 1..3, 読み込み時 +0x5c へ, 0x41af10）, u32 種類, u32 所属写真番号（+0x88）,
double × 4（左・上・右・下）。n = 3 のときだけ本体の後ろに u32（+0x8c）が続く（0x40b200 / 0x40d230）。

| 種類      | クラス                                       | このアプリでの扱い                     |
| --------- | -------------------------------------------- | -------------------------------------- |
| 2         | CPictureObject（写真枠）                     | 位置・大きさ・形・枠線を編集。他は保持 |
| 3         | CCaptionObject（文字項目）                   | 文字・項目・書式・枠線を編集           |
| 4         | CDrawObject                                  | 生バイトのまま透過（編集不可）         |
| 5         | CCMValueObject（施工管理値）                 | 位置・大きさのみ編集、中身は保持       |
| 6         | CDraftObject（参考図）                       | 生バイトのまま透過                     |
| 7 / 8 / 9 | CDrawRect / CDrawPattern / CDrawPoly（図形） | 生バイトのまま透過（表示のみ）         |

種類→クラスの対応は 0x40d230 の switch。

## 文字項目（種類 3, 保存 0x407400 / 読込 0x408610）

1. CString 表示文字（長さ 1 バイト、0xFF のとき続く u16 が長さ, 0x45c000）
2. フォント名 32 バイト（cp932, 書くときは 0 埋め）
3. 書式 44 バイト（構造体 +0x40..+0x6b, 既定値 0x407310）
4. CString 値（テンプレートでは "0"）
5. CString 項目名（DB 項目 "写真タイトル" など）
6. i32 ×4: +0x108（未確定。`+0x10c` が -1 の 14 件は同じく -1）, +0x10c（1 = 項目値, 0 = 項目名, -1 = 項目に結び付かない固定文字。実物 563 件と実機で確認）, +0x110 枠線あり（0..1 に丸める）, +0x114（0..2）
7. 版 > 1 かつ +0x114 が 0..2 のとき: u32 枠線色, i32 枠線太さ 0/1/2 = 0.1/0.3/0.7 mm（0x580578..）

書式 44 バイト（このアプリが編集するのは、影・袋文字を除く行だけ。影・袋文字（0x04, 0x0a, 0x0c, 0x18, 0x20, 0x24）は意味を確定済みだが、編集には未対応で、読んだまま保持する。未確定の 0x12, 0x13 は決して書き換えない）

実機の差分実験（2026-11-10、書式 44 バイト）: 既定の書式の文字項目（24pt・枠線あり・文字「あAbc」）の書式を 1 か所ずつ書き換えた TPL を、
`C:\現場編集長data\DB14ACCESS\Template\TEMP1x3_V\` に置いて、アルバム作成ツールの「テンプレートの適用/編集」で適用して見た（写真枠の実験と同じ手順）。

- 0x04 を 0〜7: 1 で影付き（右下に灰色の影）、2 で袋文字（灰色の縁取り）、0 と 3〜7 は効果なし。
- 0x04 = 1 で 0x20 を青にすると影が青になり、0x24 を赤にしても変わらない。0x04 = 2 で 0x24 を赤にすると縁取りが赤になり、0x20 を青にしても変わらない。
- 0x04 = 1 で 0x0a を 0 / 3 / 15 / 30: 距離が 0（影が重なる）から離れていく。0x0c を変えても影は変わらない。
- 0x04 = 1、0x0a = 30 で 0x18 を 0 / 90 / 135 / 270: 影が右 / 上 / 左上 / 下に出る（既定の -45 は右下）。
- 0x04 = 2 で 0x0c を 30: 縁取りが大きな塊になる（0x0a を変えても変わらない）。
- 0x09 は 0x08 の u16（文字サイズ）の上位バイト。1 にすると 280pt になり、文字が枠からはみ出して見えなくなる。
- 0x12 = 1 / 63、0x13 = 1、0x0a / 0x0c の 0 や 10 は、効果なしの状態では見た目が変わらない。

生成は `gen_fmt_unknown_experiment` / `gen_fmt_effect_experiment` / `gen_fmt_effect_size_experiment`、集計は `list_fmt_variants` / `fmt_12_13_by_face` / `fmt_12_13_18_per_template`（`tpl/experiment.rs`）。

## 写真枠（種類 2, 保存 0x42f840 / 読込 0x42d610）

32 バイト, u32 b8, u32 bc, CString GUID, CString, CString パス, u32 ×4, CString, u32, CString, u32,
（版の印 > 1 のとき）u32 +0xec（0x42c060）。新しい写真枠は、開いているテンプレートの写真枠（OBJ1）の
本体を引き継ぎ、無ければ `PictureBody::default()`（全 0、`+0xe0 = -1`、`+0xe8 = 3`。四角・枠線なし）を使う。これは、本体が「通常レイアウトの作成」で新規に作る写真枠の値と同じ（実機の生成物で確認、下記「検証」）。

| 位置                               | 意味                                                                                                                                         | 根拠                   |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| +0xb8（`frame_style`）             | 下位 4 ビット = 枠の形（0 四角 / 1 角丸 / 2・3 楕円）、bit 4〜7 = 枠線の太さ（0 なし / 1 細い / 2 中 / 3 太い）。実物の値は 0 / 0x11 / 2 / 1 | 実機の差分実験（下記） |
| +0xbc（`border_color`）            | 枠線の色（COLORREF）。太さが 0 のときは使われない（実物は 0）                                                                                | 同上                   |
| `cc`, `d0`, `e0`                   | 枠線の太さではない（値を変えても見た目が変わらない）。意味は未確定で、読んだまま保持                                                         | 同上                   |
| 上記以外（`d4` / `d8`, `e8` など） | 未確定。読んだまま保持                                                                                                                       | Issue #18              |

実機の差分実験（2026-11-10、現場編集長 CALSMASTER Ver.25）: 実物の TPL（1x3 縦）から、写真枠だけを並べて、値を枠ごとに変えた TPL を作り、
`C:\現場編集長data\DB14ACCESS\Template\TEMP1x3_V\` に置き（本体のインポートは、この場所へコピーする）、アルバム作成ツールの
「テンプレートの適用/編集」で適用して見た。

- `(b8, bc)` の組み合わせ（8 枠）: `(0, 0)` 四角・枠線なし、`(0x11, 赤 / 緑 / 青)` 角丸＋その色の細い枠線、`(0, 赤)` 四角・枠線なし（色は使われない）、`(0x10, 赤)` 四角＋赤い細い枠線、`(0x01, 赤)` 角丸・枠線なし、`(0x02, 赤)` 楕円・枠線なし
- 太さ（bit 4〜7 を 0〜15、下位は 1 = 角丸）: 0 なし、1 細い、2 中、3 太い、4〜15 は枠線なし（範囲外）。bit 8 以上は見た目に効かない（`0x111` / `0x211` / `0x411` / `0x811` は `0x11` と同じ）
- 形（下位 4 ビットを 0〜15、bit 4〜7 は 1 = 細い枠線）: 0 四角、1 角丸、2 楕円、3 も楕円（2 との違いは見分けがつかない）、4〜15 は四角（範囲外）
- `cc`（0 / 1 / 2 / 5）、`d0`（0 / 1 / 5）、`e0`（-1 / 0 / 5）を変えても、枠線の太さは変わらない

実物 138 件の組み合わせとも整合する（太さが 1（`0x11`）のときだけ `bc` が 0 以外）。生成は `gen_picture_frame_experiment` / `gen_picture_frame_border_experiment` / `gen_picture_frame_b8_nibble_experiment` / `gen_picture_frame_b8_shape_experiment`（`tpl/experiment.rs`）。

## カードの大きさ（推定を含む）

## 検証

- 手元の TMPEXP の全 TPL を「読む → 何も変えず書く」でバイト単位に完全一致（`roundtrip_real_samples`, 環境変数 CARD_TPL_SAMPLES）。
- 図形を含む TPL も透過で完全一致（`passthrough_shapes_roundtrip_unchanged`）。
- 本体での取り込み: 実物の TPL（1x3 縦の 2 件）は、本体のアルバム作成ツールで「テンプレートのインポートは正常に終了しました」。写真枠の `b8` / `bc` を変えた TPL の表示も実機で確認した（上記「写真枠」）。
- 新規部品の既定値: 本体（カード → カードレイアウト → 通常レイアウトの作成）で作ったカードを「テンプレートとして登録」して書き出した TPL（1x3 縦）の写真枠は、`frame_style` = 0、`border_color` = 0、`cc` = 0、`d0` = `d4` = `d8` = 0、`e0` = -1、`e8` = 3、`ec` なし（四角・枠線なし）。文字項目は、書式 44 バイトが `default_format(12)` と完全に一致し、`t108` = 0、枠線あり（色 0・太さ 0）、`border_inset` = 0、値 "0"。違いはフォント名だけで、本体は「メイリオ」、このアプリは「ＭＳ Ｐゴシック」（`new_part_defaults_match_the_real_app`）。
- 文字項目の `is_value = -1`（固定文字）: 実物 14 件はすべて項目名が空で表示文字がある部品で、本体は項目名と同じラベルとして表示する（実機で確認、#22）。
