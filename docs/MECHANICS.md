# カードテンプレート（.TPL）の仕様メモ

対象: 現場編集長 CALSMASTER Ver.25 のアルバム作成ツール `GhAlbum.exe`（MFC / x86、.NET ではない）。
`GhManageConstruction.exe` は .NET の管理画面で、テンプレートの読み書きは `GhAlbum.exe` 側にある。
アドレスは `GhAlbum.exe` の仮想アドレス。値はすべてリトルエンディアン、座標はインチ（double）。
文字列は cp932。「推定」と書いたもの以外は逆コンパイルした処理から読んだ値。

## 受け渡しの境界（カードメニュー → テンプレートのエクスポート／インポート）

```
TMPEXP\
  expinf                      "Ver7.10Template\r\n"（文字列 "Ver7" + ".10Template", 0x598d94 付近）
  TEMP{横}x{縦}_{H|V}\        H = 横向き, V = 縦向き（"%dx%d_%s", 0x585dec 付近）
    {テンプレート名}.TPL
```

### 入力区分（+8）

登録した工事の適用区分（要領）から決まる整数で、本体は「テンプレートとして登録」するたびに、開いている工事の値で書き直す
（読み込んだ TPL の値は引き継がれない）。実機で確認した（2026-11-11、#18）。

| 適用区分                        | 入力区分 |
| ------------------------------- | -------- |
| 国土交通省（一般土木H16）       | 8        |
| 国土交通省（一般土木H20）       | 14       |
| 国土交通省（一般土木H22）       | 15       |
| 国土交通省（一般土木H28）       | 15       |
| 国土交通省港湾局（一般土木R04） | 15       |
| 国土交通省（電気通信設備H22）   | 16       |
| 国土交通省（営繕工事H24）       | 17       |

- 実物 96 件は 8（15 件）・14（47 件）・15（34 件）で、8 は項目に工種・種別・細別が無い旧様式（写真タイトル・撮影年月日・撮影箇所・請負者説明文）、14 と 15 は工種・種別・細別を使う様式、という傾向が出ている。
- 別の入力区分のテンプレートも、「テンプレートの適用/編集」の一覧に出て、適用できる（電気通信設備の工事に、8 / 14 / 15 のテンプレートを適用して確認）。このアプリが新規に書く TPL は 15（`Header::default`）のままでよい。

手順: 適用区分は、工事ごとのデータベース（`C:\現場編集長data\DB14ACCESS\C0000002\db14main.mdb` と、一覧用の `db14main.mdb`）の `CONSTRUCTION.CON_TEKIYO` / `PIC_TEKIYO` にあり、アプリを止めて書き換えてから写真管理ツールを起動し直すと切り替わる（内部の名前は「国土交通省(一般土木H22)」のような形）。アルバムは「白紙から作成」し、空のカードは登録できないので、先に適用/編集で何かテンプレートを適用してから、カード → テンプレートとして登録する。

## オブジェクトの見出し（44 バイト）

`OBJn`（n = 版の印 1..3, 読み込み時 +0x5c へ, 0x41af10）, u32 種類, u32 所属写真番号（+0x88）,
double × 4（左・上・右・下）。n = 3 のときだけ本体の後ろに u32（+0x8c）が続く（0x40b200 / 0x40d230）。

| 種類      | クラス                                       | このアプリでの扱い                     |
| --------- | -------------------------------------------- | -------------------------------------- |
| 2         | CPictureObject（写真枠）                     | 位置・大きさ・形・枠線を編集。他は保持 |
| 3         | CCaptionObject（文字項目）                   | 文字・項目・書式・枠線を編集           |
| 4         | CDrawObject                                  | 生バイトのまま透過（編集不可）         |
| 5         | CCMValueObject（施工管理値）                 | 位置・大きさのみ編集、中身は保持       |
| 6         | CDraftObject（参考図）                       | 生バイトのまま透過                     |
| 7 / 8 / 9 | CDrawRect / CDrawPattern / CDrawPoly（図形） | 生バイトのまま透過（表示のみ）         |

種類→クラスの対応は 0x40d230 の switch。

## 文字項目（種類 3, 保存 0x407400 / 読込 0x408610）

1. CString 表示文字（長さ 1 バイト、0xFF のとき続く u16 が長さ, 0x45c000）
2. フォント名 32 バイト（cp932, 書くときは 0 埋め）
3. 書式 44 バイト（構造体 +0x40..+0x6b, 既定値 0x407310）
4. CString 値（テンプレートでは "0"）
5. CString 項目名（DB 項目 "写真タイトル" など）
6. i32 ×4: +0x108（未確定。`+0x10c` が -1 の 14 件は同じく -1）, +0x10c（1 = 項目値, 0 = 項目名, -1 = 項目に結び付かない固定文字。実物 563 件と実機で確認）, +0x110 枠線あり（0..1 に丸める）, +0x114（0..2）
7. 版 > 1 かつ +0x114 が 0..2 のとき: u32 枠線色, i32 枠線太さ 0/1/2 = 0.1/0.3/0.7 mm（0x580578..）

実機の差分実験（2026-11-10、書式 44 バイト）: 既定の書式の文字項目（24pt・枠線あり・文字「あAbc」）の書式を 1 か所ずつ書き換えた TPL を、
`C:\現場編集長data\DB14ACCESS\Template\TEMP1x3_V\` に置いて、アルバム作成ツールの「テンプレートの適用/編集」で適用して見た（写真枠の実験と同じ手順）。

- 0x04 を 0〜7: 1 で影付き（右下に灰色の影）、2 で袋文字（灰色の縁取り）、0 と 3〜7 は効果なし。
- 0x04 = 1 で 0x20 を青にすると影が青になり、0x24 を赤にしても変わらない。0x04 = 2 で 0x24 を赤にすると縁取りが赤になり、0x20 を青にしても変わらない。
- 0x04 = 1 で 0x0a を 0 / 3 / 15 / 30: 距離が 0（影が重なる）から離れていく。0x0c を変えても影は変わらない。
- 0x04 = 1、0x0a = 30 で 0x18 を 0 / 90 / 135 / 270: 影が右 / 上 / 左上 / 下に出る（既定の -45 は右下）。
- 0x04 = 2 で 0x0c を 30: 縁取りが大きな塊になる（0x0a を変えても変わらない）。
- 0x09 は 0x08 の u16（文字サイズ）の上位バイト。1 にすると 280pt になり、文字が枠からはみ出して見えなくなる。
- 0x12 = 1 / 63、0x13 = 1、0x0a / 0x0c の 0 や 10 は、効果なしの状態では見た目が変わらない。
- **単位の測定**（2026-11-11。1x1 のカードに文字「あ」を並べ、表示倍率 200%（192 px/in）で、赤い影・縁と黒い本体の外接矩形の差を測った）: 28pt（em = 74.7px）で影の距離 30・向き -45 → 横・縦とも 24px（向きに沿った長さ 34px）、距離 10 / 20 / 40 / 60 で 8 / 16 / 32 / 47px（距離に比例）。距離 30・向き 0 では、28pt で 34px、42pt（em = 112px）で 50px = 文字の大きさに比例（1 単位 = 0.015 em）。袋文字は太さ 20 で、28pt が 22〜23px、42pt が 34〜35px の広がり（同じく 0.015 em / 単位）。

生成は `gen_fmt_unknown_experiment` / `gen_fmt_effect_experiment` / `gen_fmt_effect_size_experiment`、集計は `list_fmt_variants` / `fmt_12_13_by_face` / `fmt_12_13_18_per_template`（`tpl/experiment.rs`）。

## 写真枠（種類 2, 保存 0x42f840 / 読込 0x42d610）

32 バイト, u32 b8, u32 bc, CString GUID, CString, CString パス, u32 ×4, CString, u32, CString, u32,
（版の印 > 1 のとき）u32 +0xec（0x42c060）。新しい写真枠は、開いているテンプレートの写真枠（OBJ1）の
本体を引き継ぎ、無ければ `PictureBody::default()`（全 0、`+0xe0 = -1`、`+0xe8 = 3`。四角・枠線なし）を使う。これは、本体が「通常レイアウトの作成」で新規に作る写真枠の値と同じ（実機の生成物で確認、下記「検証」）。

| 位置                                       | 意味                                                                                                                                              | 根拠                                               |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| +0xb8（`frame_style`）                     | 下位 4 ビット = 枠の形（0 四角 / 1 角丸 / 2・3 楕円）、bit 4〜7 = 枠線の太さ（0 なし / 1 細い / 2 中 / 3 太い）。実物の値は 0 / 0x11 / 2 / 1      | 実機の差分実験（下記）                             |
| +0xbc（`border_color`）                    | 枠線の色（COLORREF）。太さが 0 のときは使われない（実物は 0）                                                                                     | 同上                                               |
| `cc`, `d0`, `e0`                           | 枠線の太さではない（値を変えても見た目が変わらない）。意味は未確定で、読んだまま保持                                                              | 同上                                               |
| `d4`, `d8`                                 | 貼った写真の画素数（幅, 高さ）。枠が空なら 0 / 0。本体が写真を貼るときに書く。実物の (1280, 960) は 1280×960 の写真を貼ったカードから作られたもの | 実機（1600×1200 の写真を貼って登録 → 1600 / 1200） |
| `cc`                                       | 未確定。写真を貼ると 0 が -1（0xffffffff）になる（1・2・3 は保持）。値を変えても、写真を貼った直後の見た目は変わらない                            | 実機                                               |
| `d0`, `e8`                                 | 未確定。写真を貼ると `d0` = 0、`e8` = 3 に揃う（0〜7 や 1 を入れても）。実物の `e8` = 4 が何かは不明                                              | 実機                                               |
| `guid`, `c4`, `path`, `dc`, `e4`（文字列） | 写真を貼ったカードを「テンプレートとして登録」すると、全部空になる                                                                                | 実機                                               |
| 上記以外                                   | 読んだまま保持                                                                                                                                    |                                                    |

実機の差分実験（2026-11-10、現場編集長 CALSMASTER Ver.25）: 実物の TPL（1x3 縦）から、写真枠だけを並べて、値を枠ごとに変えた TPL を作り、
`C:\現場編集長data\DB14ACCESS\Template\TEMP1x3_V\` に置き（本体のインポートは、この場所へコピーする）、アルバム作成ツールの
「テンプレートの適用/編集」で適用して見た。

- `(b8, bc)` の組み合わせ（8 枠）: `(0, 0)` 四角・枠線なし、`(0x11, 赤 / 緑 / 青)` 角丸＋その色の細い枠線、`(0, 赤)` 四角・枠線なし（色は使われない）、`(0x10, 赤)` 四角＋赤い細い枠線、`(0x01, 赤)` 角丸・枠線なし、`(0x02, 赤)` 楕円・枠線なし
- 太さ（bit 4〜7 を 0〜15、下位は 1 = 角丸）: 0 なし、1 細い、2 中、3 太い、4〜15 は枠線なし（範囲外）。bit 8 以上は見た目に効かない（`0x111` / `0x211` / `0x411` / `0x811` は `0x11` と同じ）
- 形（下位 4 ビットを 0〜15、bit 4〜7 は 1 = 細い枠線）: 0 四角、1 角丸、2 楕円、3 も楕円（2 との違いは見分けがつかない）、4〜15 は四角（範囲外）
- `cc`（0 / 1 / 2 / 5）、`d0`（0 / 1 / 5）、`e0`（-1 / 0 / 5）を変えても、枠線の太さは変わらない
- 写真を貼る実験（4:3 の 1600×1200 の写真を、`cc` / `d0` / `d4` / `d8` / `e8` を枠ごとに変えた 16 枠に貼り、「テンプレートとして登録」して本体が書き出した TPL を読んだ）: 貼った直後の見た目は 16 枠とも同じ。枠は写真の縦横比に合わせて縮む（枠の高さに合わせて 1.9 → 1.2 in。左上基準）。登録された TPL では、`d4` / `d8` が 1600 / 1200 になり、`cc` = 0 が -1 に、`d0` が 0 に、`e8` が 3 に揃い、文字列は空。`b8` / `bc` と、`cc` の 1・2・3 はそのまま

実物 138 件の組み合わせとも整合する（太さが 1（`0x11`）のときだけ `bc` が 0 以外）。生成は `gen_picture_frame_experiment` / `gen_picture_frame_border_experiment` / `gen_picture_frame_b8_nibble_experiment` / `gen_picture_frame_b8_shape_experiment` / `gen_picture_photo_experiment`（`tpl/experiment.rs`）。写真は、System.Drawing で作った向き・隅が分かる JPEG（1600×1200 など）を、写真管理ツールの「追加」で取り込み、サムネイルを枠へドラッグして貼った。

## 施工管理値（種類 5, CCMValueObject 0x40f8a0）

アルバム作成ツールで、施工管理値の部品をダブルクリックすると開く「施工管理値の貼り付け」ダイアログの設定が、そのまま保存される。
設定を 1 か所ずつ（または影響が重ならない組で）変え、「テンプレートとして登録」して本体が書き出した TPL を読んで確定した（実機、#18）。

（版の印 > 1 のとき）u32 差を表示する, u32 項目文字揃え, u32 行数, 行 × 68 バイト（u32 + 32 + 32）。

| （ダイアログに無い）         | `c0`、`x144`                         | 実物 41 件ではすべて 0。`c0` = 1 / 2 / 0xffffffff、`x144` = 1 / 2 を書いても、空のカードの見た目は変わらず、読み込める（意味は未確定） |

- 本体は、読み込んだ OBJ1（拡張なし）の部品を、差を表示しない・左揃えとして扱い、保存するときは OBJ2（拡張あり、行数 0）で書く。実物の拡張ありの 2 件（行数 0）も `(0, 1, 0)` で、中央揃え・差なし。
- 「表示形式を横または縦に並べる」と、文字が表内に収まるよう文字サイズが自動で調整されることがある（ダイアログの説明）。これは保存される値ではなく、描画時の処理。
- 実物 41 件の分布は、表示個数が 1（18 件）・2（5）・3（8）・4（5）・5（5）、表示形式が 1（32）・0（6）・2（3）。ファイル名に「項目 2 種類」「3 項目」「横」「縦」を含む物とも合う。

- 2026-11-11 の追加の実験（1x1 のカードに 11 個の施工管理値を並べて適用）: `name_style` = 1 は見出しが「s1」「s2」（記号）になる。`border_weight` = 1 は枠線が描かれる。`c0` / `x144` / 差の行は、空のカードの見た目に出ない。拡張の 2 つ目（揃え）の 2・3 は左揃えのまま。生成は `gen_cm_unknown_experiment` / `gen_cm_unknown_experiment2` / `gen_cm_reject_experiment`（`tpl/experiment.rs`）。

調査用のコードは、集計が `list_cm_values`（`tpl/survey.rs`。書式のバイトと色も出す）。

## 検証

- 手元の TMPEXP の全 TPL を「読む → 何も変えず書く」でバイト単位に完全一致（`roundtrip_real_samples`, 環境変数 CARD_TPL_SAMPLES）。
- 図形を含む TPL も透過で完全一致（`passthrough_shapes_roundtrip_unchanged`）。
- 本体での取り込み: 実物の TPL（1x3 縦の 2 件）は、本体のアルバム作成ツールで「テンプレートのインポートは正常に終了しました」。写真枠の `b8` / `bc` を変えた TPL の表示も実機で確認した（上記「写真枠」）。
- 新規部品の既定値: 本体（カード → カードレイアウト → 通常レイアウトの作成）で作ったカードを「テンプレートとして登録」して書き出した TPL（1x3 縦）の写真枠は、`frame_style` = 0、`border_color` = 0、`cc` = 0、`d0` = `d4` = `d8` = 0、`e0` = -1、`e8` = 3、`ec` なし（四角・枠線なし）。文字項目は、書式 44 バイトが `default_format(12)` と完全に一致し、`t108` = 0、枠線あり（色 0・太さ 0）、`border_inset` = 0、値 "0"。フォント名も同じ「メイリオ」（以前のこのアプリは「ＭＳ Ｐゴシック」で、#28 で本体に合わせた。`new_part_defaults_match_the_real_app`）。
- 文字項目の `is_value = -1`（固定文字）: 実物 14 件はすべて項目名が空で表示文字がある部品で、本体は項目名と同じラベルとして表示する（実機で確認、#22）。

## 本体の描画で確かめたこと（v0.1.0 の実機 E2E、2026-11-11）

詳細は [RUNBOOK_v0.1.0.md](RUNBOOK_v0.1.0.md)。

- **文字の左右の余白**: 本体は、文字項目の内側に、左右合わせて 3pt より大きく 4.9pt 以下の余白を取る
  （1×3 縦の 76.9pt の列で 72pt の文字が収まり、4×5 縦の 63pt の列で 60pt の文字は折り返した）。
  自動折り返しが有効（既定）の項目で、列に収まらない文字は折り返され、行の高さからはみ出した分は描かれない。
  このアプリの描画の余白（0.5mm ずつ = 約 2.83pt）は、これより小さい。新規作成の初期配置は、余白を 7pt に見込む。
- **項目名ラベルの文字**: 「対応する項目」（`field`）がある項目名ラベルは、本体の画面で、「表示する文字」（`text`）ではなく項目名を描く。
  `text` を書き換えても、本体の画面には出ない（太字などの書式は反映される）。
- **`expinf`**: 本体が書く `expinf` は `Ver7.10Template\r\n` に続けて製品名と版（`現場編集長 CALSMASTER(25.0.0.0)`、cp932）の行がある。
  このアプリが書く 1 行だけの `expinf` でも、本体は取り込める。
- **インポートの動作**: 取り込む TPL は、置き場（`Template\TEMP{横}x{縦}_{H|V}\`）に、バイト単位で同一のままコピーされる。
  同名のテンプレートがあると、1 つずつ（または「すべて」）上書きの確認が出る。
- **適用の一覧**: 「テンプレートの適用/編集」は、いまのカードの分割数・用紙方向に合うテンプレートだけを一覧にする。
